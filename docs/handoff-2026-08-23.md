## Trap: three worktrees, one database

All worktrees share a single local Supabase stack — same `supabase_*_conductflow` containers,
same project ref in `config.toml`. There is no per-worktree database.

This already caused one false alarm. Running the suite in `Q:\cf-wt\ingest` produced 16
failures reading `Could not find the 'owner' column of 'task' in the schema cache`. The cause
was not the ingest change: the orgs branch had applied `0020_task_owner_user.sql` to the
shared database, putting the schema ahead of the ingest worktree's code.

**Before trusting any test run, confirm which branch's migrations are currently applied.**
`npm run db:reset` from the worktree you are actually testing.

Two more environment notes:

- `supabase start` fails with `LegacyStatusDbNotReadyError` if the db container is still
  `starting`. Wait for Docker's own healthcheck to report `healthy` — `pg_isready` goes green
  earlier and is not sufficient.
- `supabase db reset` recreates the Postgres container. Anything that connects immediately
  after gets `Connection terminated unexpectedly`. Wait for health again after the reset, not
  just after the start.

## What each branch contains

### `wt/ingest-bounds` — `fc03bdb`

Three `select("*")` reads in `lib/ingest/run.ts` scanned an org's entire commitment and task
history on every ingest. Each now names the columns its consumer actually reads, orders by
recency, and stops at `INGEST_STATS_ROW_LIMIT` (500).

Column lists were verified by hand against `lib/ops/map.ts` and `lib/ops/exceptions.ts`. Note
the rows are cast `as Commitment[]`, so TypeScript will **not** catch a missing column — the
test is the only guard.

- `tests/ingest/bounds.test.ts` — passes.
- Lint and build — clean.
- Full suite — 426 passed, 16 failed, all from the shared-database drift described above.

**Next session: `db:reset` on this branch alone, re-run the suite, then merge.**

### `wt/kek-rewrap` — `b559b31`

Closes the last unmet criterion of security control 3A. Adds `rewrapDataSources()` in
`lib/google/rotate.ts` and a `CRON_SECRET`-authorized `POST /api/cron/kek-rewrap`,
deliberately **not** on a cron schedule — rotation is an operator action taken in lockstep
with an env change, and `POST` keeps Vercel's `GET`-only scheduler from firing it.

468 tests pass, lint and build clean, no migration required.

Introduces `DATA_SOURCE_KEK_VERSION`, which is load-bearing: unset means 1, and it must be
raised in the same deploy that swaps the key. The full rotation runbook is §10 of
`docs/google-enablement-runbook.md`. The order there is not advisory — setting
`DATA_SOURCE_KEK` without first setting `DATA_SOURCE_KEK_PREVIOUS` breaks every existing
grant irrecoverably.

Known gaps: no preflight endpoint reporting how many rows are still behind, and nothing stops
an operator removing the previous key too early. No test exercises the HTTP route itself.

## Google enablement — 6 of 9 done

Full walkthrough lives in `docs/google-enablement-runbook.md`. The demo account is
`joinconductflow@gmail.com`.

Done: four APIs enabled, the demo account added as a Cloud project Owner, consent screen and
scopes configured with both accounts as test users, redirect URIs and JavaScript origins
registered, the Picker browser API key created and restricted, and both public env vars set
in Vercel production followed by a successful `--prod` deploy.

`conductflow-sooty.vercel.app` currently aliases deployment `conductflow-qf9699ccq`, which is
the first build carrying `NEXT_PUBLIC_GOOGLE_CLIENT_ID` and
`NEXT_PUBLIC_GOOGLE_PICKER_API_KEY`.

Remaining, all human browser work:

1. Sign into production as the demo account. First sign-in auto-creates an empty single-owner
   org named "joinconductflow's workspace"; there is no rename screen, so renaming is a SQL
   update in the Supabase editor.
2. Grant Drive, Calendar and Gmail at `/settings`, one at a time.
3. Ingest five prepared transcripts, then walk the demo end to end.

Two rules that silently break the demo, both found in code rather than docs:

- A Drive template's **file name must contain the word "template"** — `pickTemplate()` in
  `lib/google/context.ts` filters candidates on `/template/i`.
- A calendar event must fall on the **same date typed into `/ingest`**, and the day window is
  a **UTC** day because `organization.timezone` defaults to UTC. An evening event in a
  western timezone lands on the next UTC date and disappears.

Testing mode caps consent at 100 users and expires refresh tokens after **7 days**. Re-grant
all three capabilities the morning of any demo.

## Still not built, and honest about it

- **Gmail threading.** Needs a restricted read scope, which widens the CASA assessment. No
  spec exists.
- **Document creation.** ConductFlow drafts text and pushes email drafts; it cannot create a
  Google Doc. `lib/google/drive.ts` is read-only by construction and no document action
  exists in `EDITABLE_ACTIONS`. Worth knowing: `drive.file` already permits creating files,
  so this needs **no new scope and no CASA change** — roughly a day's work mirroring the
  existing Gmail draft path, plus a `draft_client_document` action that belongs in
  `ALWAYS_NEEDS_APPROVAL`.
- **Verification and CASA Tier 2.** Needs a domain you own and costs money. Testing mode is
  the correct place to be for a pitch.
- **`EXTRACTION_MODEL`** in `lib/agent/schema.ts` is still `openai/gpt-oss-120b`. Switching
  to `anthropic/claude-sonnet-5` is the largest quality lever available and costs money —
  ask before changing it.
